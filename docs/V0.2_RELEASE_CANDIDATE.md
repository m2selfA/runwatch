# runwatch v0.2.0 Release Candidate Contract

Status: **R16 local qualification complete; final fresh GitHub CI / tag / GitHub Release pending**.

## Product scope

v0.2.0 preserves runwatch's durable-authority architecture and advances the Windows desktop surface into a Human Run Console. `runwatchd` remains canonical for Run/Attempt/Observation/Delivery state, scheduler and Local Process lifecycle, SSH observation and continuation delivery. GUI/MCP/CLI remain clients of that authority.

The release includes:

- Windows Human Run Console dashboard/detail/attention/service/Hosts surfaces;
- agent-neutral manual Local Process, Slurm and LSF Run authoring through `submit_run_v2`;
- Windows resident Task Scheduler hardening and GUI no-console behavior;
- Windows fresh-runner package + visual fixture gates;
- Linux glibc-2.17 runtime CI artifact gate.

It does **not** add retry/resubmit Attempt semantics, generic remote shell/file editing, scheduler administration dashboards, GUI branch rebind/force-ack, or new coding-agent productization.

## Compatibility contract

v0.2.0 keeps local IPC:

```text
protocol_version = 1
service          = runwatchd
storage          = sqlite-wal
```

Compatibility is capability-based; `hello.version` remains diagnostic. v0.2.0 adds GUI-oriented read/probe capabilities without invalidating the Pi-first v0.1 required capability set. The current daemon also advertises the existing Pi continuation capabilities and the frozen Codex reference capability.

`runwatch.db` remains canonical SQLite WAL storage. A historical `runs.jsonl` is still one-time read-only migration input only when the canonical Runs table is empty.

## Upgrade contract

Supported in-place upgrade remains:

1. close the tray GUI;
2. use the **old package's** `runwatch.exe autostart --remove` to quiesce/stop/unregister the owned resident runtime;
3. replace the entire sibling package directory;
4. run the new package's `autostart --install`, `daemon-status`, then Pi `runs_doctor` as applicable.

Stopping runwatch observation is not scientific Run cancellation. R16's Job 31837 replay proves scheduler work survives the binary replacement gap and is rediscovered through the same canonical store. R13 independently qualifies the real fixed-name Task Scheduler ACL, PT1M non-resurrection and ordinary Limited-user disable/re-enable path.
